# Example 01 — Tony Pineapple

[English version](README.md)

## Статус

**Реальный production-кейс beFruitbe.**

**Финальная версия:** принята компанией  
**Публикация:** TikTok / Instagram / YouTube  
**Результат:** около 3 000 суммарных просмотров на трёх площадках

---

## Исходная задача

Команда передала короткое ТЗ:

> Сделать короткое видео по механике динамичного cinematic edit с пресс-конференцией и последующей серией эффектных сцен с главным героем.

В качестве визуального референса использовалась узнаваемая механика сцены пресс-конференции из супергеройского кино.

Задача заключалась не в копировании исходного видео, а в адаптации его драматургической и монтажной механики под собственных персонажей.

---

## Концепция

Главным персонажем стал:

### Tony Pineapple

Антропоморфный ананас в роли уверенного центрального героя.

Другие персонажи:

### Strawberry Reporter

Антропоморфная клубника-корреспондентка.

### Press Room

Зал заполнен другими антропоморфными фруктами, выступающими в роли журналистов и интервьюеров.

---

## Основная структура ролика

Сценарий строился из двух частей.

### Часть 1 — Press Conference

Главный герой находится перед прессой.

Корреспондентка задаёт вопрос.

Tony Pineapple делает эффектное заявление, после которого начинается переход ко второй части.

### Часть 2 — Character Edit

Под динамичную музыку идёт серия коротких сцен с Tony Pineapple.

Задача второй части — не объяснять продукт словами, а создать запоминающийся образ персонажа и задать энергичную стилистику будущего контента.

## Character Reference Pipeline

Перед видеогенерацией я сначала зафиксировал внешний вид ключевых персонажей.

Для каждого основного героя создавались изображения с разных сторон.

Для двух ключевых персонажей использовалась примерно следующая схема:

```text
Character
    ↓
Front View
Side View
Alternative View
    ↓
несколько генераций каждого ракурса
    ↓
выбор подходящего варианта
```

Всего на этом этапе было создано около **18 изображений**.

Цель — сохранить узнаваемость персонажей между разными видео-сценами.

## Объём генерации

Для итогового ролика потребовалось примерно:

```text
≈18 character/reference images
+
≈4–5 video generations
+
voice generation
+
lip sync
+
final editing
```

Это хороший пример того, что даже относительно короткий AI-ролик требует нескольких стадий и контроля результата.

---

## Основная техническая проблема

Главной задачей в этом видео было сохранение стабильного окружения между генерациями.

При первых попытках фон мог немного меняться между сценами.

Это снижало визуальную continuity.

---

## Как проблема была решена

Я корректировал prompts, точнее фиксируя:

- окружение;
- стиль сцены;
- расположение объектов;
- визуальные характеристики пространства.

После нескольких изменений окружение стало значительно стабильнее.

---

## Почему сначала создавались character references

Одна из проблем генеративного видео — изменение персонажа между сценами.

Поэтому вместо независимой генерации каждого кадра я сначала подготовил reference-наборы персонажей.

Логика:

```text
Сначала:
зафиксировать персонажа

Потом:
генерировать сцены с ним
```

а не:

```text
каждый раз заново описывать героя текстом
```

Это помогало сохранять:

- форму персонажа;
- основные черты;
- визуальный стиль;
- узнаваемость между сценами.

## Human-in-the-Loop

Несмотря на использование AI на большинстве производственных этапов, финальные решения оставались за человеком.

Я проверял:

- внешний вид персонажей;
- continuity;
- фон;
- движения;
- качество генераций;
- соответствие сцен исходной идее.

После этого команда beFruitbe утверждала готовый результат.

## Что я вынес из этого ролика

Этот кейс показал мне важность предварительной подготовки персонажей перед генерацией видео.

Вместо процесса:

```text
Prompt → Video
```

более устойчивый подход выглядел так:

```text
Character Design
      ↓
Reference Set
      ↓
Scene Prompt
      ↓
Video Generation
      ↓
Continuity Check
      ↓
Iteration
```

Также я увидел, насколько сильно детализация окружения в prompt влияет на стабильность сцены между отдельными генерациями.
